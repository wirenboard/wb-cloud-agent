# Wiren Board Agent

[![Coverage Status](https://coveralls.io/repos/github/wirenboard/wb-cloud-agent/badge.svg)](https://coveralls.io/github/wirenboard/wb-cloud-agent)

Агент с использованием аппаратной подписи для получения обновлений с wirenboard.cloud.
[Подробная документация](https://wirenboard.com/wiki/Wiren_Board_Cloud)

## Как установить

Обновите список пакетов на контроллере и установите пакет

```
apt update && apt install wb-cloud-agent
```

## Как использовать

Для подключения контроллера через веб-интерфейс воспользутейсь [разделом настроек](https://wirenboard.com/wiki/Wiren_Board_Cloud#%D0%94%D0%BE%D0%B1%D0%B0%D0%B2%D0%BB%D0%B5%D0%BD%D0%B8%D0%B5_%D0%BA%D0%BE%D0%BD%D1%82%D1%80%D0%BE%D0%BB%D0%BB%D0%B5%D1%80%D0%B0_%D0%B2_%D0%BE%D0%B1%D0%BB%D0%B0%D0%BA%D0%BE).
Чтобы получить ссылку для подключения контроллера в консоли, выполните:
```
wb-cloud-agent
```

## Работа демона

Для запуска с отдельным конфигурационным файлом:

```sh
wb-cloud-agent run-daemon PROVIDER -c /path/to/wb-cloud-agent.conf
```

Демон ждёт подключения к MQTT, затем публикует `starting` и сохранённую ссылку
активации, даже если облако пока недоступно. После стартовых запросов публикуется
`connecting`, затем результат связи с облаком. Недоступность MQTT или облака
обрабатывается повторными попытками в том же процессе. При восстановлении MQTT
повторно публикуются метаданные и последние значения.

SIGINT/SIGTERM завершают процесс с кодом 0. Текущий curl-запрос может закончиться
до остановки; задержки между попытками прерываются сразу. При завершении демон
пытается удалить свои retained-топики с подтверждением брокера за время до 5 секунд;
неудачная очистка записывается в лог. Общий список провайдеров не удаляется.
Начальный отказ MQTT-авторизации даёт код 2, ошибка конфигурации — 6.

Сборщик метрик также ждёт подтверждённого MQTT-подключения и восстанавливает RPC
после переподключения. Остановка во время повтора отправки не сохраняет UID ещё
не отправленных метрик.

Локальные тесты описаны в [tests/README.md](tests/README.md).
